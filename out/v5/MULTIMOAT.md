# 常に同じスコアにする仕組み ＋ 複数の堀の採点（2026-07-26 実装）

## Ⅰ. なぜスコアが動いていたか
エンジンは決定論的で、同じ入力からは必ず同じ点が出る。動いていたのは**入力（堀の判定）**で、
それを毎回私が記憶と印象から作り直していた。実際、同じ会社が数日で 78.4 → 69.3 → 75.0 と動いた。

## Ⅱ. 対策：堀の証拠台帳を唯一の源にする
```
moat_evidence.json  （堀の証拠。ここだけがスコアを動かせる）
        ＋
out/v5/_machine.json（機械値。SEC/EDINET由来で審査者は触らない）
        ↓  tools_build_pack.py（決定論的生成）
out/v5/v5_all_pack.json（門に取り込むパック）
```
- **スコアが動いたら、必ず `moat_evidence.json` の差分が git に残っている。** 残っていない変動は起こり得ない。
- 各パックの `_meta.audit.source_ledger` に台帳の sha256 を刻む＝どの版の証拠で採点したか後から特定できる。
- 検査コマンド2本:
  - `python tools_build_pack.py --check` … 台帳から再生成して既存パックと一致するか
  - `node tools_reproducible.mjs`         … 同じパックを2回採点して全銘柄一致するか

実行結果（2026-07-26）:
```
✓ 再現した: 28社 / 台帳 sha256=a31c045c03ef
✓ 再現した: 28社すべてが2回とも同じスコア
```

## Ⅲ. 複数の堀（v9.10）をエンジンに実装
従来は会社ごとに堀を1組（dom/irr/rep/dur）しか持てず、複数事業の会社は審査者が1つに潰すしかなかった。
**Microsoftは私が消費者Windows寄りの弱い値（irr=50）で代表させており、M365とAzureの堀は採点に一度も入っていなかった。**

### 合成の形
```
各事業ごとに堀を採点  moat_i = 幾何平均([dom,irr,rep,dur],[.30,.30,.25,.15])
会社の堀 = 最強の堀 + Σ 独立ボーナス      （上限 +8、moatIdx全体の上限96）
  独立ボーナス_k = (moat_k / 最強) × 売上比_k × C_k      C = [20, 10]（第2、第3）
```
- **平均にしない**。平均は弱い堀が強い堀を薄め、事業を増やすほど不利になる＝門の思想（一点突破が最強）と逆行する。
- **単一事業を罰しない**。ASML・eWeLL・レーザーテックはボーナス0で従来どおり。
- **上限8**は、複数の堀が一点突破（ASML moatIdx 89.2）を超えないための蓋。
  独立した堀は「壊れにくさ」を上げるが「強さ」は上げない、という考え方。

### 独立と認める条件（3つすべて）
1. 10-K/有報の**報告セグメント**として売上が開示されている（自己申告の事業数では加点しない）
2. 売上比 **15%以上**
3. `indep_reason` に**壊れ方が違う理由**が書かれている（同一顧客・同一サイクルは独立ではない）

3が空なら加点ゼロ。実装で強制している（`indep===true && indep_reason` が非空のときだけ加点）。

> **例: 東京エレクトロンは複数の装置事業を持つが独立ではない。** 顧客も需要サイクルも同一（半導体設備投資）で、
> 片方が崩れる局面ではもう片方も同時に崩れる。よって多堀ボーナスの対象外＝76.9 のまま。

### Microsoft の実測
| 事業（10-K FY2025 売上・百万ドル） | 売上比 | 堀 |
|---|---|---|
| M365/Office (Productivity & Business Processes) 120,810 | 42.9% | **74.5** |
| Azure (Intelligent Cloud) 106,820 | 37.9% | 66.1 |
| Windows/Gaming/Search (More Personal Computing) 54,094 | 19.2% | 66.1 |

会社の堀 = 74.5 + min(8, Azure +6.7 / MPC +1.7) = **82.5**（従来 66.1）
→ **総合 74.8 → 78.5**

## Ⅴ. 残っている課題
- **ボーナス係数 [20,10] と上限8は検証された値ではない**。n=1（Microsoft）で置いた初版。
- **セグメント別の堀は Microsoft しか作っていない**。NVDA（ゲーム約10%＝15%未満で対象外）、
  V・KLAC・ASML は実質単一事業なので影響なし。ソニーのような多事業銘柄を審査する時に台帳を足す必要がある。
