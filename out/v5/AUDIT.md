# 採点系の第三者監査（2026-07-27・6視点並列監査）

対象: v5証拠規則＋エンジンv9.10-9.12＋全銘柄再採点の結論「352社中75超は4社のみ」。
方法: 独立した6エージェント（エンジン論理/実挙動/証拠事実/データ整合/プロトコル整合/順位頑健性）による並列監査。
4視点が完走、2視点（プロトコル整合・順位頑健性）と反証フェーズはセッション上限で未完。
**最重要2件は本体が追試して確定済み。**

## 総合判定: 方向は正しいが「4社のみ」という結論は誤り

### 【最重大・追試確定】TSM の irr=50 は誤審 — 正しくは5社通過
前回の審査は「20-Fに顧客の移行年数・費用・構造的事実の記載を確認できず」として irr=50 とした。
**これは見落とし。** FY2025 20-F Item 4 に、設計基盤（EDA/PDK/ライブラリ/IP・OIP）が
プロセス技術ごとに専用で、移行には作り直しを要するという構造的事実が明記されている。
v5規則（irr70=構造的事実を原本で示せる時）とアドバンテスト判例に照らせば irr=70 が妥当。

**追試実測: irr70 で TSM 73.3 → 75.8（堀の柱 68→73、柱割れ解消）＝投下閾値75を超える。**

さらに dom も脆い: TrendForce通年69.9%で「境界上→下の段(70)」としたが、四半期実勢は70〜72%で
dom85なら単独でも75.5と覆る。一方 NVDA は二次集計86%で無条件 dom85 —— **出典への厳格さが
TSMとNVDAで逆転しており、規則の適用が不均一**。

### 【エンジンの実バグ・実測確認済み】
1. **CCF_MOATS汚染（+0.8を実測）**: applyFields を通らない compute 経路（手入力→採点、loadIt、
   ccfRescoreAll）では前銘柄の moats がグローバルに残留し、別銘柄の moatIdx に混入する。
   autoSave で __moats ごと誤保存され得る。※バッチハーネス(tools_rerun_all.mjs)は銘柄ごとに
   applyFields を呼ぶため「4社」の集計自体はこの汚染の影響外。汚染するのはUI操作の台帳。
2. **moatsのみパックのドラフト誤隔離**: ccfIsDraftObj は13定性キーしか見ず、moats 配列を無視。
   検問が applyFields（moats→top-level複写）より先に走るため、堀を moats にだけ書いた正当な
   パックが「機械値ドラフト」として g7wait: へ隔離される。
3. **生成器とエンジンの欠測処理不一致**: tools_build_pack.py の moat_one は dom=None→1、
   エンジン ccfMoatOne は→50（v9.11未移植）。最強セグメント選択が両者で食い違い得る。
   エンジン側も irr/rep/dur 欠測は→1 で幾何平均が崩壊する。
4. **順位の逆転8件**: 三本柱を全通過した MSI 74.3・SPGI 73.7 が、柱割れで足切りされた
   HWM 74.9・KLAC 74.4 より下に並ぶ。「柱通過＞柱割れ」という教義と画面の並びが矛盾。
5. **崖の複合**: v9.12 の pm=70 境界の不連続は仕様（+1.5点を実測）だが、上流の gmPt が
   階段関数のため営業利益率0.05ptの差で総合+3.3点動くケースがある。

### 【データの問題・確認済み】
6. **352社の母数が汚れている**: 無効宣言済み out/jp/_superseded_v3 の23社が混入。
   santec(6777) が2エントリ重複し、**無効なv3版の方が9.8pt高い**。
   審査済みの日本株3社（オービック4684・SMC6273・キーエンス6861）が欠落。実質351社。
7. **rerun_all.json が旧版のままコミットされている**: v9.12とHEI/TSM再審査より前の値で、
   現行エンジンと21社食い違う。このJSONだけ読むと「HEI 79.1/TSM 76.8を含む6社通過」という
   誤った結論を再現してしまう。RERUN.md の「再現」節がこの旧データを再現正本として指している。
8. **運用ファイルの陳腐化**: kanshi_list.json の omega75plus は14社のまま（新結果は4社基準なら
   要更新）。out/next_earnings.json の elite も同様。
9. **台帳内の小さな矛盾**: moat_evidence.json の MSFT top-level が単堀時代の旧値のまま
   （build は moats 優先のため実害なし）。_meta.audit に旧 hanshou と新 hanshou_v5 が併存。
   KLAC「プロセス制御56%」に出典名がなく、v5規則（出典名つきのみ採用可）に自ら違反。

### 結論
- 再現性の仕組み（台帳→決定論的生成→二重採点検査）は機能しており、方向は正しい。
- しかし **「75超は4社のみ」は誤りで、TSMの原本根拠により最低5社**。かつ柱割れ上位
  （KLAC/V/NVDA/東エレク）は証拠1段で動くナイフエッジ上にあり、確定的な数として扱えない。
- エンジンにはUI経路限定の実バグが3件（汚染・誤隔離・欠測不一致）。
- データ衛生（旧値・重複・無効版混入）が「再現できるが正しくない」状態を作っている。
